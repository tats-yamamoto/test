## このファミリーの考え方

新規事業を「**企画 → 実証 → 事業化**」のフェーズで進める。中核の**事業ロジック軸は3フェーズ共通**で、フェーズごとに「頭（動機）」と「尾（計画／検証／投資判断材料）」が変わるだけ。

### 共通の事業ロジック軸（全フェーズ共通）
```
起案者・チーム（／想い） → 顧客課題 → 戦略合理性 → 提供価値 → 解決策
   → 競争優位性（差別化） → ビジネスモデル・収益性
```

### フェーズ別の構成（＝種別）

| 種別 | 目的 | 構成（共通軸 ＋ フェーズ固有） |
|---|---|---|
| **A. 企画書** | アイデアを通す（やらせてほしい） | 表紙 → 起案者・**想い** → [共通軸] → **活動計画及び予算** → 収支計画 → 以上 |
| **B. 実証実験計画書** | PoCの承認を得る | 表紙 → 起案者/チーム → [共通軸] → **リスク適応** → **検証に向けた準備** → 予算計画 → 収支計画 → 以上 |
| **C. 事業計画・投資提案** | 投資を得る | 表紙 → **エグゼクティブサマリ** → 起案者 → [共通軸（競争優位性は **市場規模→競合比較** に展開）] → ビジネスモデル・収益性 → **PoC実績** → 収支計画 → 以上 |

- A企画書＝最軽量、**想い**を前面に。
- B実証実験＝**検証設計が肝**（仮説→検証方法→成功基準）。
- C事業計画＝**事業性の証明が肝**（市場規模・競合・PoC実績）。

## 各スライド型

### 起案者・チーム（／想い）
- 役割: 誰がやるか・なぜやりたいか（企画書は"想い＝動機"を強く）
- メッセージライン例: 「『本気ですか？』仕入先の一言に応えた "本気のTPS"」(デジタルTPS 着想)
- 必須要素: 起案者/チーム ／（企画書）原体験・想い
- 図表タイプ: 文章

### 顧客課題
- 役割: 誰のどんな課題か。新規事業の出発点
- メッセージライン例: 「標準化ができていない背景には『何から始めたらいいかわからない』」(デジタルTPS)
- 必須要素: 顧客（誰の）／ 課題の構造 ／ なぜ未解決か
- 図表タイプ: 概念図

### 戦略合理性
- 役割: なぜ自社/自部署がこの課題に取り組むのが戦略的に正しいか
- 必須要素: 全社・事業戦略との整合 ／ 自社が取り組む必然性（保有アセット・立ち位置）
- 整えメモ: **「Wovenでやる意義」等の"なぜこの主体か"はここに吸収**。案件特有なら独立項目で足す

### 提供価値
- 役割: 顧客に何を届けるか
- 必須要素: 提供価値 ／ 主な対象者
- 図表タイプ: 表（工程／提供価値／対象者）
- 実例: デジタルTPS s15

### 解決策
- 役割: どう実現するか（プロダクト/サービスの中身）
- 必須要素: ソリューション概要 ／ 主要機能・アプローチ

### 競争優位性（差別化）
- 役割: なぜ勝てるか・他と何が違うか ※画像の「差別化・競争優位性」を統一
- 実例: 「TPSの思想による改善知見がベース」「トヨタ直伝」(デジタルTPS s16)
- 必須要素: 差別化要因 ／（事業計画は **市場規模・競合比較** へ展開）

### ビジネスモデル・収益性
- 役割: どう価値提供し、どう儲けるか
- 実例: ツール提供＋導入支援＋教育支援で長期ロイヤリティ (s18) ／ 収益性=提供サービス/売上見込/考え方 (s19)
- 必須要素: 課金構造 ／ 主要顧客 ／ 収益の考え方

---
### ＜A 企画書＞活動計画及び予算
- 役割: 何を・いつ・いくらで進めるか
- 必須要素: 活動マイルストーン ／ 体制 ／ 予算
- 図表タイプ: 大日程ガント＋費用表 →`図表パターン.md`

### ＜B 実証実験＞リスク適応
- 役割: 想定リスクと対応（実証ゆえの不確実性に備える）
- 必須要素: リスク ／ 影響 ／ 対応
- 図表タイプ: リスク表 →`図表パターン.md`

### ＜B 実証実験＞検証に向けた準備 ★実証実験の心臓部
- 役割: 何を検証し（仮説）、どう検証するか（方法・指標・体制）
- 必須要素: **検証仮説 → 検証方法・KPI → 成功基準** ／ 必要な準備（データ・環境・協力先）
- 整えメモ: 叩き台の「検証に向けた準備」を "仮説→方法→成功基準" の型に**補強**

### ＜C 事業計画＞市場規模
- 役割: 市場の大きさ（投資判断の根拠）
- 実例: TAM / SAM / SOM（年間1兆）(s20)

### ＜C 事業計画＞競合比較
- 役割: 競合の中での立ち位置
- 実例: サービス名/提供価値/貢献度/ターゲット/価格 (s21) ＋ ポジショニングマップ (s22) →`図表パターン.md`

### ＜C 事業計画＞PoC実績
- 役割: 実証で何がわかったか（事業性の裏付け）
- 実例: PoC#1 標準化支援・物情リアルタイム生成 (s9-12)

### ＜C 事業計画＞エグゼクティブサマリ
- 役割: 全体像を1枚で掴ませる
- 実例: 「デジタルTPSプラットフォーム（仮）は…改善活動を支援する」(s2)

### 予算計画 / 収支計画（共通の尾）
- 役割: お金の計画
- 必須要素: 費用内訳 ／（事業計画・収支は）売上・利益の見通し
- 図表タイプ: 費用表・収支表 →`図表パターン.md`

## トーン
- 企画書: 想い・熱量を込めつつ、論理（課題→価値→解決）も通す
- 実証実験計画書: 検証の客観性・段取りの確かさ
- 事業計画・投資提案: 事業性の説得力（数字・市場・競合）

## 整えメモ（画像の叩き台 → どう整えたか）
1. 3種別を**フェーズ（企画→実証→事業化）共通の事業ロジック軸＋フェーズ別の頭尾**として統合
2. 「差別化・競争優位性」→「**競争優位性（差別化）**」に統一
3. 実証の「検証に向けた準備」を **"仮説→検証方法→成功基準"** の型に補強
4. **「Wovenでやる意義」は汎用から除外** → "なぜこの主体でやるか" は「戦略合理性」に吸収（案件特有なら独立項目で追加可）
5. 事業計画固有の **市場規模・競合比較・PoC実績・エグゼクティブサマリ** はフェーズC専用として保持
- ⚠ 企画書・実証実験は**見本pptx未取得**。実例は事業計画(デジタルTPS)から流用。見本が出たら `doc-pattern-extraction` で見直す
