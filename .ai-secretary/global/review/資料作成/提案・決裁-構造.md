---

## 目的・読者・ゴール
- 目的: 仕事を受注する（社外）／ 社内決裁を得る（予算・契約・方針の承認）
- 読者: 顧客（社外見積）／ 部長・本部長（HB決裁・決裁説明）
- ゴール: お金・人を出してもらう／決裁を通す

## スライド構成（標準フロー）

```
表紙 → ①ご提案概要 or 目次 → ②背景(課題) → ③範囲・スケジュール(大日程)
   → ④活動内容(作業項目・工数) → ⑤体制 → ⑥費用・契約 → ⑦リスクと対策 → 以上 →(Appendix)
```

## トーン差分（社外／社内）
- **社外＝見積提案（RXSWIN）**: 訴求的。「ご提案」「〜いたします」。**コスト低減アピール**と**リスクと対策**で受注を後押し。
- **社内＝決裁説明・HB決裁（設計情報流通・2Qモデラー）**: 決裁を仰ぐトーン。**背景を厚く**（投資の正当性）。費用・契約を明確に。
- **継続案件（2Qモデラー）**: 背景は「**おさらい**」で軽く、工数・費用が主役。

## 各スライド型

### ① ご提案概要 / 目次（冒頭）
- 役割: 結論サマリ（社外）／ アジェンダ（社内）
- **社外型「ご提案概要」**: プロジェクト名 / 概要 / 期間 / 契約形態 / 工数 / 金額 を**先出し**
  - 実例: 「準委任契約 / 28.45人月 / 44,798千円 / 2026.1.5–3.31」(RXSWIN s2)
- **社内型「目次」**: 活動背景 / 全体スケジュール / 活動内容 / 体制 / 費用・契約内容（設計情報流通 s2）
- **継続型「プロジェクト概要（おさらい）」**: 既知前提で軽く（2Qモデラー s2）

### ② 背景（課題提起）
- 役割: なぜこの取り組みが必要か。課題を積む
- メッセージライン例:
  - 「法規要件であるRXSWIN対応が義務化されるため、TMCとして対応が必要」(RXSWIN s3)
  - 「まずは法規対応に必要なSW関連情報を集約することが必要。人手では困難かつリスク高のため、IT支援により業務成立させる」(RXSWIN s5)
- 必須要素: 背景（なぜ今） / 課題（何が困難） / 解決の方向性
- ボリューム: 社内決裁は厚く（設計情報流通＝活動背景9枚）／社外見積も背景5枚／継続案件は薄く
- 図表タイプ: 文章＋概念図

### ③ 範囲・スケジュール（大日程）
- 役割: 取り組み範囲と時間軸を示し、**「今回の提案範囲」を明示**
- 図表タイプ: ガント → `図表パターン.md`「大日程ガント」
- 実例: RXSWIN s8/s11、設計情報流通 s12「今回の提案範囲」、2Qモデラー s3

### ④ 活動内容（作業項目・工数）
- 役割: 具体的な作業項目と工数内訳
- 必須要素: No. / 項目（分類） / 内容 / 備考 / 工数(人月) の表＋合計
- 図表タイプ: 工数表 → `図表パターン.md`「工数・費用表（作業項目表）」
- 実例: RXSWIN s12（開発準備/インフラ/連携/新規作成/更新/管理、合計28.45人月）、設計情報流通 s13（No./分類/実施内容/成果物/工数）

### ⑤ 体制
- → 共通基盤「体制図」。実例: SRK体制 (2Qモデラー s4)、ステークホルダー体制 (RXSWIN s14)

### ⑥ 費用・契約内容
- → 共通基盤「費用・契約内容」＋ **社外見積はコスト低減を添える**
- 図表タイプ: 見積表 → `図表パターン.md`「工数・費用表（見積表）」
- コスト低減 実例: 「IT費用低減 ▲9,730千円（生成AI活用 ▲7,364 / Docker→Podman ▲154 / 低単価BP配置 ▲2,484）」(RXSWIN s15)

### ⑦ リスクと対策（社外提案で特に重視）
- 役割: 想定リスクと対策を示し、発注の不安を消す
- 必須要素: # / リスク / 影響 / 対策 の表
- 図表タイプ: リスク表 → `図表パターン.md`
- 実例: 「ステークホルダーが多い → 要件調整の長期化 → 動くものを見せて議論推進＋2回のトライで見直し」(RXSWIN s16)

## 作法メモ
- **社外見積**: 概要で金額先出し → 背景で課題 → 計画/工数 → 見積（コスト低減訴求）→ リスクで締め
- **社内決裁**: 背景を厚く（投資の正当性）→ スケジュール → 活動内容 → 体制 → 費用・契約
- **継続案件**: 背景は「おさらい」、工数・費用が主役
