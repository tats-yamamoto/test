# レイアウト・図版規定（pptxネイティブ作成の一次ソース）

> - 抽出元: 横山一さん 報告5件（本部長報告 25/10・HB報告 25/01・03・04・07）を python-pptx で実測＋代表スライドを画像確認（2026-05-29）
> - 位置づけ: **python-pptx で pptx を直接組むときの寸法・配置・図版の規定**。
>   - 配色・フォント・文字サイズ → `colors_and_type.css`
>   - 構成（並び・各スライドの役割）・トーン → `報告-構造.md` / `提案・決裁-構造.md` / `新規事業-構造.md`
>   - 定番図版の作り → `図表パターン.md`
> - この規定は「実物に寄せる」ことが目的。**叩き台で文字が小さい/バラつく・図のスペースが小さい問題の再発防止**が主眼。

## 0. キャンバス

- 16:9 / **13.333 × 7.5 inch**（= 1920×1080px, 144px/inch）
- 安全マージン: 左右 **0.5in** ／ 上 0.16in ／ 下 0.3in
- 1スライド = 1メッセージ。詰め込まない（§3）。

## 3. 余白・密度（実物は"余白で語る"）

- 1スライドの要素は **5〜7個まで**を体感上限に。足りなければ分割。
- 箇条書きは **行間 1.3前後**、項目間にスペース。ぎっしり詰めない。
- 文字で埋めない。**空白を恐れない**（実物は余白がたっぷり）。
- 見出し → 内容のまとまりを、余白でグルーピングする。

## 4. 図版ゾーン（★今回の主眼：図に主役を張らせる）

実物は **最大図が全幅×4.5in（スライドの過半）** を占める。図中心で組む。

### 標準の図エリア
- **全幅型**: 幅 ≈12.3in × 高さ **3.8〜4.5in**（本文ゾーンの過半）。
- **2カラム型**: 左に図（≈7〜7.5in）＋ 右に箇条書き（≈4.5in）。図が主、文字が従。

### レイアウト型（どれかに寄せる）
1. **図中心**: 上=メッセージライン / 中=大きな図1点 / 下=含意1行
2. **図＋説明（2カラム）**: 左=図（過半） / 右=要点箇条書き（16pt）
3. **工程**: オレンジのシェブロン（角丸右向き矢印）を縦/横に積む（→`図表パターン.md`）
4. **対比**: 2〜3ブロックを横並び＋下に結論バー

### 図の作法
- **「自社範囲／自社活動」は淡色（ピーチ＝accent1薄）の角丸コンテナで囲み**、ラベルを付ける（実物の体制図の作法）。
- **注記はティールの吹き出し**（speech bubble）。
- **出所**は図の下に 11pt グレーで（「出所：〜」）。
- 図は使い回しの仮置きでも、サイズだけは大きく取る（小さい図を中央にぽつんと置かない）。

## 4.5 画像・イラストの使いどころ ＋ プレースホルダ規定

> 横山一の報告（社内ステータス報告）は図解中心で写真が少なく、ここは見本だけでは学べない+α。**外部の信頼できる知見**で補った（出典・信頼性は §11）。

### 判断基準（最重要・スライドの種類で決めない）
- **「聞き手に頭の中で思い浮かべてほしいもの」があるスライドには、視覚（写真 or イラスト）を挟む。** 「課題だから／解決策だから」とスライドの種類で決めない。対象＝モノ・機器・場所/現場・完成イメージ・Before/After・将来像・「文字で説明するより絵の方が早い」概念 等。下の表は“よくある例”であって、そこだけという意味ではない。
- **進め方**: 視覚が効くスライドはこちらから積極的に提案する。視覚を置かない判断をしたら**理由を明示**する（黙って省略しない）。**何を・どこに入れるか迷うときは、勝手に決めず先にユーザーとすり合わせる**。
- 維持: データ・表そのものは図表（写真にしない）。装飾目的の画像は置かない。

### 原則（写真・画像）
- **1スライドに強い画像を1枚**。小さい画像を散らさない。可能なら大きめ／全幅、テキストは画像の余白に重ねる（Reynolds）。
- **本物・高品質・統一トーン**。クリシェ／安っぽいstock写真・合成は避ける。複数使うなら「同じ写真家が撮った」ような統一感（Duarte）。
- **意味のある画像だけ**置く（装飾目的の画像は置かない）。
- **データは写真でなく図表**（グラフ／インフォグラフィック）。表・データ・計画スライドに写真を貼らない。

### どのスライドに何の画像（この資料ファミリーの目安。例であり固執しない）
| スライド | 画像の役割 | 例 |
|---|---|---|
| 表紙 | コンセプトの世界観（ヒーロー） | 誰もが動ける街の俯瞰 |
| **課題／顧客（共感）** | **人を見せる＝共感**。困っている当事者・現場 | 段差・EV停止で立ち往生する車椅子／ベビーカー利用者 |
| Why Now／現場の声 | 顧客の現場 | 段差前で止まる配送ロボット |
| **解決策／プロダクト** | **UIモックアップ・デバイス・製品** | ナビアプリ画面、センシング機器 |
| ビジョン／将来像 | 体験の到達点 | 街を自由に動く様子 |
| 実証現場 | 場所・対象 | 実証エリア／対象ロボット |
| 事業フェーズ・競合・収支・体制・ガント・成功基準 | **写真は使わない**（図表が主役） | — |

### プレースホルダ規定（叩き台では実物を入れず「枠＋指示」を置く／写真もイラストも同じく枠を置く）
図版ゾーン（§4）に **淡グレー・破線枠**のプレースホルダを置く（**絵文字は使わない**＝§4.8。見出しは `［画像挿入エリア］` 等のテキスト＋四角）。中身は種類に応じて:

- **(A) 写真・リアルCG**: ① `［画像挿入エリア］`（見出し）／② **何の画像か（日本語1行）**＝意図（共感／製品／現場 等）が分かる説明／③ **生成プロンプト（英語1文）**＝画像生成AIにそのまま入れられる（被写体・状況・スタイル・`no text`・縦横比）
- **(B) イラスト**: ① `［イラスト挿入エリア］`（見出し）／② **何のイラストを・どこに・なぜ（何をイメージさせたいか）** を日本語で／③ **素材の当て**＝イラストや等の無料素材の検索語/イメージ。やわらかく・説明的に伝えたい場面向け

→ 写真・イラストどちらも、後で実物に差し替える前提で、叩き台段階は**枠＋指示のまま残す**（「未確定を隠さない」運用）。

## 4.8 「人が作った質感」の作法（脱・テンプレ感）＋ 色使い ＋ 手法ローテ ★重要

> 「AI/テンプレっぽさ」は、横山一の実物（人が作った資料）と比べると見える。引き算と"控えめな多様性"で人の質感に寄せる。

### 脱・テンプレ感（基調）
- **本文ページは色付きカードで囲わない**。黒/グレー文字＋余白＋細罫＋軽い mono パネルで構成（横山一の本文ページは囲み少・余白多）。
- **絵文字は使わない**（🔎🖼 等）。`要検討` `［画像挿入エリア］` 等のテキスト＋小さな図形で表す。
- **「未確認／要検討」注記は"レイアウト非干渉のフローティング付箋"**: 本文・図版のレイアウトは注記が**無いものとして**組み、注記は**後から該当箇所の上にやや雑に重ねる**だけ。注記のために枠・余白・カラム・行を**確保しない**（コンテンツブロックとして扱わない）。理由＝注記は確定でなく一時メモであり、消す/差し替えても本体レイアウトが動かないようにするため。※ 枠を確保する**画像プレースホルダ（§4.5）とは別物**。
- 中央揃えに頼らず**左揃え**を基本に（**例外: メッセージライン（18pt, y≈0.78in）のみ CENTER**）。

### 色使い（横山一準拠）
- **黒（ink）の本文・見出し ＋ グレー（muted）の補足が主役**。スライドは黒・グレー・白が基調。
- **オレンジ（accent1）は"差し色"**＝ティック／番号／キーワード／自社・主作業 に限定。**見出し全部を色にしない**（見出し文字は黒、色はティックで差す）。
- 他色は **§5の役割表に従う**（ティール＝注記/対比・濃赤＝リスク・緑＝達成のみ・青＝多カテゴリ図のみ）。**1スライドのアクセントは2〜3色まで**。「青緑黄を図のカテゴリ分けに」と安易に多色化しない（§5「段階・フェーズ・工程の色」参照）。

### 統一モチーフ（バラけさせない錨）
- **小さなオレンジのティック（縦バー）＋ 骨格（グレータイトル＋グラデ罫＋黒太字メッセージ＋©フッター）＋ 型スケール＋余白リズム** を全スライド共通の"クセ"にする。レイアウトが変わってもこれで同じ資料に見える。

### グループ化の手法ローテ（同じ手で固めない・多用しない）
中身に応じて下記から選び、**特定の手法（特に細罫グリッド）を全スライドで反復しない**。線・図形は使ってよいが**控えめ**（1枚に罫線数本／パネル・帯は1〜2個まで）:
- 余白カラム ／ 大きい番号①②③ ／ 色ティック付きリスト ／ 軽い mono パネル ／ 画像と本文の2分割 ／ 表 ／ シェブロン・フロー
- 囲み・色・線は**「意味がある所」中心**（図・表・自社範囲・カテゴリ分け）。装飾目的では足さない。

## 5. 色の意味と配色ルール（横山一実測 ＋ 配色理論で裏付け）※色値は colors_and_type.css

実物は色数を絞り、**色に役割を持たせている**。意味のない色を足さない。

### 配色の大原則（なぜ色を絞るか）
- **アクセントは1スライド2〜3色まで**。増やすと「全部目立つ＝何も目立たない」になる（プレゼン配色の鉄則／60-30-10）。
- 基調は **黒（本文）・グレー（補足/基盤）・白（背景）** の無彩色（≒60-30%）。色はアクセント（≒10%）に回す。
- **オレンジ（ブランド色）の補色＝ティール/青（寒色）**。暖色×寒色が最も調和するので、第2アクセントは原則ティール。
- **同じ図・同じ資料の中で色の意味を一貫させる**（フェーズを色で示すなら全スライドで同じ割り当て）。

### 色の役割（この割り当て以外で色を使わない）
| 色 | 役割 | 使ってよい場面 |
|---|---|---|
| ink黒 / muted灰 文字 | 本文 / 話題ラベル・補足 | 全スライド |
| グレー（node / lt2 塗り） | 他社・他部署・基盤・参考・既存・**前段階** | 図のベース、他社ノード |
| **accent1 オレンジ（主アクセント）** | 自社=主役・自社の工程/作業・強調・今フォーカスする要素 | 最も使う差し色（"差し色"なので多用しない） |
| ピーチ（accent1 薄） | 自社活動／自社範囲の**コンテナ枠** | 体制図・範囲図 |
| **accent2 ティール（副アクセント／オレンジの補色）** | 注記・吹き出し／対比概念の一方（B2B↔B2C 等）／特に強調したい一点 | オレンジと対にする時 |
| accent3 濃赤 | **リスク・警告・必達ライン**・サブチーム/重要ノード | リスク表、必達基準 |
| accent6 緑 | **達成・完了・ポジティブ指標のみ** | 成功ノード、達成セル。段階・カテゴリの色分けに流用しない |
| accent5 青 | **原則ティールに寄せる**。体制図など"会社/部署を多数分ける"カテゴリ図に限り追加カテゴリ色として可（muted寄り） | 多カテゴリの分類のみ |
| accent4 琥珀 | 注意・ハイライト（淡塗り＋色文字でセル強調 等） | 表の強調セル |

### 段階・フェーズ・工程の色（よくある誤用の防止）
- 「点→線→面」「Phase0→1→2」などの**進行・成長段階は、色相を増やして区別しない**。
  - ✅ 正: **グレー（初期/基盤）→ オレンジ（自社が広げる範囲）** の濃淡・トーンで進行を表す。対比が要る箇所だけティール。
  - ❌ 誤: 段階ごとに青・緑・橙…と別色を割り当てる（意味のない多色化）。
- ステップフロー（実証手順 等）は **自社アクション=オレンジ／外部・他社=グレー** で十分。ゴール（達成）だけ緑にしてよい。
- 1スライドで使う色は**意味のあるものだけ**。装飾目的で色を増やさない。

## 6. 表スタイル

- **ヘッダ行**: 濃グレー（dk2 か ink）地・白文字・太字・中央。
- **セル**: 白地・黒文字・左寄せ（数値は右寄せ）。
- **グリッド**: line `#BFBFBF` を 0.75pt。重い黒罫にしない。
- **セル文字 11〜12pt**。行高は内容に追従。
- 強調行/セルのみ淡色塗り＋色文字（例: 必達=赤、ブルーオーシャン=淡amber）。
- **重複列を作らない**: 「課題」列と「必要アクション」列のように内容が重なる列は片方に寄せる。

## 8. 固定要素

- **フッター（全スライド共通）**: 左下「© TOYOTA SYSTEMS CORPORATION All Rights Reserved.」10pt muted。
- **ページ番号**: 右下。表紙・章扉は省略可。
- **関係者外秘スタンプ**: 社内秘の資料は右上に置く（`assets/stamp-confidential.png`）。叩き台・検討中はその旨をフッターか欄外に明記。
- **🔎要検討（叩き台用）**: ベージュ（callout）の小さな欄外注記。原文を勝手に埋めない・消さない。

## 9. python-pptx 実装メモ

- 文字は **latin / ea / cs の3系統**に同じ書体を指定（日本語が別書体に化けるのを防ぐ）。
- 影は既定でオフ（`shape.shadow.inherit=False`）。
- 表は "No Style, No Grid" にしてセル罫を自前で引く（#BFBFBF 0.75pt）。
- グラデ罫は gradFill（3stop: C81528 / E83820 / F6AC19, 角度0）。
- **OneDrive上の既存pptxを読むときは全バイト読込→BytesIO**で開く（部分ハイドレートで zip 末尾が欠けて `is_zipfile` が落ちるため）。
- 描画QAは PowerPoint COM（PowerShell）で各スライドPNG出力→目視（LibreOffice不要）。
