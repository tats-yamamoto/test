## 文体・トーン（全種別共通）

- **メッセージライン文化**: 各スライド上部に「そのスライドで言いたいこと1文」を置く。※"文面"はここで生成、"上部に帯で配置"はデザイン側（Claude Design）。
- 体言止め・簡潔さ。**事実と主観（所感）を分ける**。
- 専門用語は**初出時に説明**を差し込む（下記「用語説明」型）。
- 自部署/自社の担当範囲は図中に**明示**（「ご提案範囲」「ご報告範囲」「今回の提案範囲」）。
- 締めは「**以上**」。本編後の詳細・補足は「**Appendix**」「**（ご参考）**」。

## 共通スライド型

### 表紙
- 役割: 主題・種別・日付・作成者を示す
- 必須要素: タイトル（テーマ＋"状況/報告/提案/決裁説明"等） / 日付 YYYY/M/D / 部署（例: 電技改革支援部 DX企画G） / 作成者 / 報告・決裁区分（本部長報告・HB決裁 等があれば）
- 図表タイプ: —
- 実例: 「品番設計支援(デジカケ)状況 / 2025/3/26 / 本部長報告」/「RXSWIN認証業務_トライ向け開発 25年度4Q分 / 見積提案書 / 2025/12/10 / 電技改革支援部 DX企画G」

### 大日程（ロードマップ）
- 役割: 数年〜数四半期スパンの全体像・現在地・自社範囲を示す
- メッセージライン例: 「2026年12月にRxSWIN機能を号口リリース目標」「主に設計の法規認証対応業務に関して複数テーマを五月雨式に推進」
- 必須要素: FY/四半期の時間軸 / テーマ別の帯 / ▼マイルストーン / 「ご提案・ご報告範囲」の明示
- 図表タイプ: ガント → `図表パターン.md`「大日程ガント」
- 実例: FY25–27、テーマ別（部品リスト出力 / VIN×SWIN紐づけ / システム開発）(RXSWIN s8)

### 体制図
- 役割: 関係する会社・部署・人物と役割、自社の担当範囲を示す
- 必須要素: 会社/部署のくくり / 人物（名前＋役割記号 GM/SN/B/S 等） / 自社範囲の明示 / （ユーザー側推進の中心人物などの注記）
- 図表タイプ: 体制図 → `図表パターン.md`「体制図」
- 実例: TS/NBX/TISA/法規認証部… を会社ごとに配置、「ご提案範囲」を枠で明示 (RXSWIN s14)、ユーザー側中心人物に注記 (1015 s8)

### 用語説明
- 役割: 専門用語・略語を読者（上位者）に分かる言葉で説明
- メッセージライン例: 「RxSWIN（Regulation X Software Identification Number）とは、特定の法規に関連するソフトウェア構成を一意に識別する番号」
- 必須要素: 用語名 / 正式名称（英語展開） / 平易な定義 / なぜ重要か
- 図表タイプ: 文章＋概念図
- 実例: 「RxSWINとは」(1015 s3 / RXSWIN s4 / 2DEE Appendix)、「SEAMlessとは」(1015 s13)

### 費用・契約内容（提案・決裁で必須）
- 役割: 工数・費用・契約条件を提示
- 必須要素: 契約形式（準委任/請負） / 御見積工数（人月） / 金額 / 作業期間 / 作業場所 / 前提条件 / 検収条件
- 図表タイプ: 表 → `図表パターン.md`「工数・費用表」
- 実例: 「準委任契約 / 28.45人月 / 44,798千円」(RXSWIN s15)、「請負契約 / 28.72人月」(設計情報流通 s15)

### Appendix / ご参考
- 役割: 本編を補強する詳細（体制詳細・関連図・タスク洗い出し・用語補足）
- 配置: 本編→「以上」→「Appendix」の順
- 実例: 体制詳細 (RXSWIN s19)、RxSWINとは/G-CIS/組織業務分担 (2DEE s18-20)、各案件の関係図 (設計情報流通 s17)
