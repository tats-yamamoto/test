# 優先順位判断スキル

## 前提: 必ず参照するデータ

1. 全PJの `tasks.json` — 全タスクの期限・ステータス・背景
2. 全PJの定期タスク（`daily/`, `weekly/`, `monthly/` 配下の tasks.json）
3. `.ai-secretary/global/weekly-schedule.json` — 今日の会議スケジュール
4. `.ai-secretary/global/user-profile.md` — 勤務スタイル、隙間時間の使い方
5. `.ai-secretary/global/patterns.json` — 優先度傾向、作業時間実績
6. 該当PJの `knowledge.md` — PJの緊急度・フェーズ
7. 該当PJの `people.md` — 関係者の期待値・力関係

## 優先順位の判断基準（優先度順）

### Tier 1: 今日やらなければならない
- 今日が期限（hard deadline）のタスク
- 期限切れのタスク（即座に対応が必要）
- リマインダーで通知されたアクション

### Tier 2: 今日やるべき
- 3日以内に期限が来るタスク（hard/soft）
- 多段レビュープロセスの次ステップが今日のもの（マイルストーン期限）
- waiting状態が長い（5日以上）タスクのフォロー
- 関係者から催促があったもの

### Tier 3: 今日やると効果的
- asap タスク（他タスクとの比較で判断）
- 進行中タスクの次のアクション
- 今日の会議に関連するタスクの準備
- 今週中の soft deadline

### Tier 4: 余裕があれば着手
- starts_at が今日のタスク（着手可能になったばかり）
- 期限が1週間以上先だが、早めに着手すべきもの（規模が大きい等）
- 定期タスクで今期間中にまだ未完了のもの

## スケジュールとの組み合わせ

1. 今日の会議スケジュールから隙間時間を算出
2. 各隙間の長さに応じてタスクを割り当て:
   - **長い隙間（2時間以上）**: 重めの作業（報告書作成、開発、深い検討）
   - **短い隙間（30分〜1時間）**: 軽めの作業（メール返信、レビュー、確認作業）
   - **15分未満**: 定期タスク（日次チェック等）
3. 会議の前後で関連タスクを配置（会議の準備→会議→会議のフォロー）

## 出力形式

```
## 今日の優先順位

🔴 今日が期限
  1. <タスク名> | <PJ> | 期限: MM/DD (hard) | 理由: ...

🟠 3日以内
  2. <タスク名> | <PJ> | 期限: MM/DD | 理由: ...

🟡 進行中・次のアクション
  3. <タスク名> | <PJ> | 次: ... | 理由: ...

🔵 余裕があれば
  4. <タスク名> | <PJ> | 理由: ...

📋 定期タスク
  ⬜ <日次タスク名>
  ⬜ <週次タスク名>（今週未完了）

💡 提案
  - 「<タスク名>は2週間放置されています。取り下げますか？」
  - 「<タスク名>は来週着手可能になります。段取りを考えますか？」

⏰ 隙間時間の使い方
  - 10:00-13:00（3h）→ #1 報告書ドラフト
  - 14:30-15:00（30m）→ #3 メール返信
  - ...
```

## ユーザーが修正した場合

ユーザーが優先順位を変更した場合:
1. 変更内容を `patterns.json` の `priority_tendencies.observations` に記録
2. 次回以降、同種の状況で修正後の判断を反映する
