# 段取り・マイルストーン設計スキル

## 前提: 必ず参照するデータ

1. 対象タスク（tasks.json）— 期限、期限タイプ、背景、制約
2. 該当PJの `knowledge.md` — レビュープロセス、制約条件
3. 該当PJの `people.md` — レビュアーの好み・スケジュール・力関係
4. `.ai-secretary/global/user-profile.md` — 報告ライン（TL→GM→部長）、勤務スタイル
5. `.ai-secretary/global/weekly-schedule.json` — 今週の会議密度
6. `.ai-secretary/global/patterns.json` — 過去の実績（time_estimation, task_decomposition, planning_history）

## 段取り設計の手順

### 1. タスクの性質を把握する

- タスクの種類を判定: 報告書作成 / 開発・PoC / 調査・検討 / 庶務 / etc.
- 多段レビューが必要か判定（knowledge.md の報告ライン参照）
- 他タスクとの依存関係を確認

### 2. マイルストーンを逆算で配置する

最終期限から逆算して以下を配置:

#### 多段レビューがある場合
```
最終期限 ←← 部長レビュー ←← GMレビュー ←← TLレビュー ←← ドラフト完成 ←← 骨子作成 ←← 着手
```

各段階で必要な完成度:
- **骨子段階**: 構成案と各セクションの要点のみ
- **TLレビュー用**: 本文を肉付けしたドラフト
- **GMレビュー用**: TLのFBを反映した修正版
- **部長レビュー用**: 最終版に近い精度

#### レビュー不要の場合
```
最終期限 ←← 完成・提出 ←← 作業 ←← 着手
```

### 3. 日数を見積もる

- `patterns.json` の `time_estimation.accuracy_log` に同種タスクの実績があれば参照
- `task_decomposition` に分解パターンがあれば参照
- `planning_history` に過去の段取り実績があれば参照
- 実績がない場合は一般的な見積もりで提案し、その旨を明示する

### 4. スケジュール制約を反映する

- ユーザーの勤務日（user-profile.md: 月〜金）
- ブロック日・休暇の回避
- 会議密度が高い日は作業時間が限られることを考慮
- レビュアーのスケジュール傾向（people.md に情報があれば）

### 5. バッファを確保する

- レビューの差し戻しを見込んで、各レビュー段階の後に1日のバッファを置く
- 過去の傾向で「このタイプは想定より長くかかる」パターンがあれば反映

## 出力形式

```
## 段取り提案: <タスク名>

最終期限: YYYY-MM-DD（hard/soft）

| # | マイルストーン | 目標日 | 備考 |
|---|---|---|---|
| 1 | 骨子作成 | MM/DD | 構成案レベル |
| 2 | ドラフト完成 | MM/DD | 本文肉付け |
| 3 | TLレビュー提出 | MM/DD | ○○さん |
| 4 | FB反映 | MM/DD | バッファ1日含む |
| 5 | GMレビュー提出 | MM/DD | △△さん |
| ... | ... | ... | ... |

根拠:
- 過去の同種タスク実績: 平均N日
- 会議密度: MM/DD は会議が多いため作業時間限定
- レビュアー: ○○さんは結論ファースト重視（people.md）
```

## 提案後の手順

1. 「この段取りでマイルストーンを登録しますか？」と確認
2. 承認されたら task-manager スキルで tasks.json の milestones に追加
3. `patterns.json` の `planning_history.observations` に段取りパターンを記録
