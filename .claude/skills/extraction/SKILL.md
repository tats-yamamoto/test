# 抽出スキル

VTT/テキストメモから情報を抽出する「抽出モード」。**メインの会話の中で実行する。**

> ⚠ 設計上の前提: 抽出は別コンテキスト（サブエージェント）に切り出さない。抽出後に「それは違うよね、本当はこう言っていた」とソース（VTT本文）を見ながら修正する会話が頻繁に発生するため、**元のVTTをメインのコンテキストに保持したまま**抽出・確認・修正を行う。VTTが巨大でコンテキストに載りきらない場合のみ、読み込みを分割するか一次要約を挟む。

## 抽出すべき情報

入力（VTTまたはテキスト）から以下を抽出する:

### 1. タスク
- タイトル（簡潔に）
- 推定カテゴリ（PJ名や業務分類）
- 推定期限（「来週まで」→ 具体的な日付に変換）
- 期限タイプ（hard / soft / asap / none）
- 依頼者
- **担当者（assignee）**: 自分がやる話なら null（または "ヤマモト"）。他人のアクションをPM視点でウォッチする場合は担当者名を指定
- 背景（なぜこのタスクが発生したか）
- 制約条件

※ 会議・レビュー・面談は**タスクにしない**（`.claude/rules/data-handling.md`「タスクとマイルストーンの使い分け」参照）。親タスクの milestones / related_meetings で扱う。
※ 同一担当・同一期限・同じ親タスクに収まる修正作業は1つの todo にまとめる（細かく分けすぎない）。

### 2. PJの決定事項・論点・新情報

拾った各項目を**確度で仕分ける**（`core-principles.md`「発散と収束の区別」に従う）:

- **決定**（実際に決まった）: 明示的なクローズ・担当/期限の確定・意思決定権者のクローズがあるもの
- **検討中／論点**（まだ決まっていない・発散）: 案や方向性は出たが結論なし。「そうですね」等の相槌・沈黙・ノリ・「一旦」での同調しかないものはここ
- **保留／持ち帰り**: 明示的に先送りされたもの

⚠ **トラップ検知**: 「誰かが発散（思いつき・方向性）を述べる → 他者が相槌で同意 → 明示的クローズなし」のパターンは、議事録上は「合意・決定」に見えても**決定に倒さず「検討中／論点」**に分類し、「表面同意の可能性・本心未確認」と注記する。原因は力関係（上下）に限らず、忖度・同調圧力・その場のノリも含む。people.md / global/review/people の立場・力関係は「同意の質」を読む材料の一つにする。

- 新しい制約や方針変更（これも決定か検討中かを区別する）
- 新しい用語

### 3. 関係者情報
- 新しく登場した人物（名前、役職、役割）
- 既存関係者の新しい情報

### 4. レビューFB（あれば）
- 自分の成果物への指摘・ダメ出し・修正要望
- レビュアーは誰か、どの成果物（タスク）への指摘か、具体的な指摘点

## 抽出後の必須フロー

1. **抽出結果を一覧でユーザーに提示する**（タスク／**決定**／**検討中・論点**／新規情報を分けて表示）。加えて「**要確認**」枠を設け、決定か検討中か曖昧な項目をまとめて提示し、確度をユーザーに確認する（1件ずつ詰問しない。明示的クローズ＋担当/期限が揃ったものは要確認に回さず決定として扱う）

2. **新規関係者の確認**
   - 新しい人名が出てきた場合、**カタカナ表記でユーザーに確認**してから登録する
   - 音声認識の漢字変換を信用しない（既知の誤変換は knowledge.md を参照して補正する）

3. **行間のヒアリング**（以下を必ず問う）
   - 「表向きの決定と実際の方向性にズレはありますか？」
   - 「『決まった』ように見える項目で、実は誰かの発散・その場の同調だったものはありますか？」（表面同意の確認）
   - 「VTTに残っていない補足情報（口頭での合意、雰囲気、力関係の変化など）はありますか？」
   - 「次のアクションで特に注意すべきことはありますか？」

4. **ユーザーの承認を得てからデータを更新**
   - タスク → 該当PJの tasks.json に追加（**task-manager スキル**の手順に従う）
   - 決定 → knowledge.md の `## 決定事項` に、**検討中・論点** → `## 論点・検討中` に書き分けて追記（**knowledge-base スキル**）。行間（駆動者・同意の質・決定権者のサイン有無）も添える
   - 新規関係者 → people.md（PJ単位 + global）に追記（**knowledge-base スキル**）
   - 勝手に更新しない。必ず承認後に実行する

5. **タスク登録時の追加提案**
   - 大きなタスクにはマイルストーン分解を提案する（**planning スキル**）
   - 既存タスク群への位置づけ・優先度を提案する（**prioritization スキル**）

6. **レビューFBの記録**（自分の成果物への指摘が含まれる場合）
   - **learning スキルのセクション3（レビューFB記録）を自動で起動**し、対象タスクの `review_history` と `global/review/people/<レビュアー名>.md` への記録を提案する（承認後に書き込み）
