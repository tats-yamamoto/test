# 朝のブリーフィング生成スキル

## 生成手順

### 0. 現在時刻の確認

`date` コマンドで今日の日付・曜日・時刻を確認する。

### 1. データ読み込み

以下のデータをすべて読み込んでください:

- `.ai-secretary/global/user-profile.md` — 今日の曜日が勤務日か、ブロック日か、定例会議があるか
- `.ai-secretary/global/patterns.json` — 繰り返しタスク、作業傾向
- `.ai-secretary/global/reminders.json` — 秘書のアクションキュー（リマインダー）
- 全PJの `tasks.json` — 全タスクの期限・ステータス
- 全PJの `daily/tasks.json`, `weekly/tasks.json`, `monthly/tasks.json` — 定期タスク
- `.ai-secretary/global/weekly-schedule.json` — 今週の会議スケジュール
- 全PJの `knowledge.md` — PJの現在地（必要に応じて参照）

### 2. ブリーフィング構成

以下の順序で情報を提示してください:

#### リマインダー処理（最初に実行）

`reminders.json` を読み、`trigger_date <= 今日` かつ `done == false` のものを処理する:

- **`add_to_schedule`**: `details` の内容を `weekly-schedule.json` に追加する
- **`notify_user`**: ブリーフィング内の「アラート」セクションに `details.message` を表示する
- **`check_and_notify`**: `details` に記載された確認を行い、結果をユーザーに報告する

処理したリマインダーは `done: true` に更新し、`reminders.json` を保存する。
※ リマインダーの処理結果はブリーフィング内で自然に報告する（「リマインダーにより追加しました」等の機械的な表示は不要）

#### 今日の定期タスク

定期タスクの完了判定には `completion_log` を使用する:
- **日次**: 今日の日付（YYYY-MM-DD）が completion_log に存在するか確認。なければ未完了として表示
- **週次**: 今週の週番号（YYYY-Www）が completion_log に存在するか確認。なければ未完了として表示。締切ルール（deadline_rule）に基づいて今日が対応日かも判断する
- **月次**: 今月（YYYY-MM）が completion_log に存在するか確認。なければ未完了として表示。月末が近い場合（残り5営業日以内）は特にリマインド

表示形式:
- 完了済みの定期タスクは「✅ 済」と表示（安心感のため）
- 未完了の定期タスクは「⬜ 未」と表示し、対応を促す
- 日次タスク → 週次タスク → 月次タスクの順で表示

#### スケジュール概要
- 今日の曜日、勤務日/ブロック日
- 今日の会議（weekly-schedule.json から、status が scheduled のもの）
  - 会議の目的（purpose）・準備物（prep）があればそれも表示
  - 関連タスクとの紐づけを提案（会議のPJ・参加者から推測）
- 会議の隙間時間の見通し（長い隙間=重め作業可、短い隙間=軽め作業向き）

#### 今日やるべきタスクの提案（優先順位付き）
- 🔴 今日が期限（hard）のタスク
- 🟠 3日以内に期限が来るタスク
- 🟡 進行中のタスク（次のアクションを明示）
- 🔵 asapタスク（他との優先度を比較して提案）

各タスクに対して:
- なぜ今日やるべきかの根拠
- どの隙間時間（重め/軽め）に入れるかの提案

**マイルストーン表示ルール:** サブタスク（milestones）があるタスクは、進捗 `[完了数/全数]` を表示し、直近期限のサブタスクを次の行に `└` で表示する:
```
t-20260401-002 | 賞与考課 | todo | 4/17 | [1/4]
  └ MS記入(4/3), CDP記入(4/3)
```

#### アラート
- 期限切れのタスク
- waiting状態が長い（5日以上）タスク → 「フォローしますか？」
- 繰り返しタスクの発生時期が近い場合
- starts_at（着手可能日）が1週間以内に到来するタスク → 「もうすぐ着手可能になります」とリマインド

#### 秘書からの提案
- 「やらなくてもよさそう」なタスクの指摘（2週間以上放置、催促なし等）
- 「そろそろこれに着手しませんか？」（期限までの逆算から）
- パターンに基づく助言（「このタイプのタスクは想定より1日多くかかる傾向があります」等）

### 3. 出力のトーン

- 秘書として簡潔かつ親しみやすく
- 一覧の羅列ではなく「今日はこう進めてはどうですか？」という提案型
- ユーザーの作業傾向（user-profile.md の work_style）を踏まえたアドバイス
