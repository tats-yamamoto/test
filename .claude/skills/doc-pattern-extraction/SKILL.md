# 資料パターン抽出スキル

## 役割

資料見本フォルダ（`資料見本/`：プロジェクトルート直下）の pptx を解析し、**種別ごとの「構造テンプレ」**を `.ai-secretary/global/review/資料作成/` に生成・更新する。

最終的な使われ方: ここで作る構造テンプレは、別途のプロンプト生成スキルが読み込み、Claude Design へ渡す「資料作成プロンプト」の素材になる。

**本スキルは「構造」担当**（並び・役割・トーン）。**デザイン（配色・フォント・文字サイズ・余白・図版の置き方）は別管理**＝同じ `資料作成/` 内の `colors_and_type.css`（配色・フォント・文字サイズ）＋ `レイアウト・図版規定.md`（寸法・余白・図版ゾーン・色の意味）。これらは見本の**実測**で整備し、Claude Design 経由でも python-pptx ネイティブ作成でもデザインの拠り所になる。構造抽出中にデザイン上の気づき（実測すべき寸法・図の型）が出たら、本テンプレではなくデザイン側ファイルに反映する。

### 抽出する／しない（線引き）

| 抽出する（構造・コンテンツ設計） | 抽出しない（デザイン＝Claude Design側） |
|---|---|
| スライドの並び・各スライドの役割 | 配色（HEX）・フォント |
| メッセージライン（主張1文）の**文面と型** | メッセージラインを「上部に帯で置く」配置 |
| レイアウトの**型**（1カラム/2カラム/図中心/表中心） | 余白・装飾・罫線・ロゴ・ページ番号体裁 |
| 文体・トーン・定型表現／お作法 | |

## 種別

- **報告**
- **提案・決裁**（見積提案＋決裁説明を統合。社外顧客向け＝訴求トーン／社内決裁向け＝決裁トーン の差分で扱う）
- **新規事業**（企画書 / 実証実験計画書 / 事業計画・投資提案。事業ロジック軸が共通。見積提案とは別骨格）
- ＋ **共通基盤**（全種別横断）／**図表パターン**（横断）

## 出力物（`.ai-secretary/global/review/資料作成/`）

| ファイル | 中身 |
|---|---|
| `共通基盤-構造.md` | 表紙 / 大日程 / 体制図 / 用語説明 / 費用・契約 / メッセージライン / Appendix / 文体・トーン共通 |
| `報告-構造.md` | 趣旨 or 目次 / 背景・概要 / 取り組み状況(本体) / 今後 / ★所感・課題・学び |
| `提案・決裁-構造.md` | 背景(課題) / 範囲・スケジュール / 活動内容 / 工数・見積 / 体制 / リスクと対策（社外=訴求・コスト低減訴求、社内=決裁トーン） |
| `新規事業-構造.md` | 企画書 / 実証実験計画書 / 事業計画・投資提案 の3フェーズ。共通の事業ロジック軸＋フェーズ別の頭尾 |
| `図表パターン.md` | 大日程ガント / 体制図 / 工数・費用表 / リスク表 / ポジショニングマップ |

### 各スライド型のスキーマ（共通）

各スライド型は以下で記述する:

- **役割**（このスライドで何を伝えるか）
- **メッセージライン例**（主張1文の型）
- **必須の構成要素**
- **図表タイプ**（文章／表／ガント／体制図／概念図／マップ）
- **実例（見本から）** ← 抽象論にせず、必ず見本の実文を引く

## 手順

### 1. 見本スキャン

`資料見本/*.pptx` を解凍し、各スライドのテキストを抽出する（pptx は zip。`System.IO.Compression` で `ppt/slides/slideN.xml` の `<a:t>` を読む）。コアスニペット:

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
Get-ChildItem '資料見本\*.pptx' | Sort-Object Name | ForEach-Object {
  Write-Output ("##### " + $_.Name + " #####")
  $zip = [System.IO.Compression.ZipFile]::OpenRead($_.FullName)
  $slides = $zip.Entries | Where-Object { $_.FullName -match '^ppt/slides/slide[0-9]+\.xml$' } |
            Sort-Object { [int]([regex]::Match($_.Name,'[0-9]+').Value) }
  foreach ($s in $slides) {
    $r = New-Object System.IO.StreamReader($s.Open()); $xml = $r.ReadToEnd(); $r.Close()
    $t = [regex]::Matches($xml, '(?s)<a:t>(.*?)</a:t>') | ForEach-Object { $_.Groups[1].Value }
    $n = [regex]::Match($s.Name,'[0-9]+').Value
    Write-Output ("[s$n] " + ($t -join '  |  '))
  }
  $zip.Dispose()
}
```

- スライド枚数が多く全文が要る場合は `-First N` で先頭runだけ取り構成を掴む → 必要箇所だけ全文取得、と二段にする。
- 構造把握は基本テキストで足りる。ただし**計画系（大日程・開発計画・実施計画）など"体裁"が重要なスライドは画像化して体裁を抽出する**（時間軸の段組み・シェブロン帯・色分けの意味・▼マイルストーン・範囲の破線枠などはテキストに出ない）。
- **画像化の方法（実証済み）**: PowerPoint COM で PNG 出力 →（Read で画像確認 → `図表パターン.md` に落とす）。
  ```powershell
  $ppt = New-Object -ComObject PowerPoint.Application
  $pres = $ppt.Presentations.Open($path, -1, 0, 0)   # ReadOnly・バックグラウンド
  $pres.Slides.Item($n).Export($outPng, "PNG", 1280, 720)
  $pres.Close(); $ppt.Quit()
  ```

### 2. 種別分類

ファイル名＋中身から各資料を分類する:

- ファイル名に「報告」 → **報告**
- 「提案」「決裁」「見積」、または 背景→範囲→活動内容→体制→費用 の骨格 → **提案・決裁**
- 「事業計画」「投資提案」かつ 市場規模／収益性／ビジネスモデル／競合 を含む → **事業計画・投資提案**
- 判別に迷う資料はユーザーに確認する（カタカナ作成者名・新種別が出たら特に）。

### 3. 既存テンプレの有無で分岐 ★

- **新規（テンプレ未作成）**: 種別ごとに構造を抽出してテンプレを生成する。
- **見直し（既存テンプレあり）**: 新しい見本を既存テンプレと突き合わせ、以下を差分として抽出する。
  1. **新パターン**（既存テンプレにないスライド型・お作法）
  2. **揺れ・反例**（既存の「必須」が今回欠けている／順序が違う等）
  3. **実例の追加**（より良い実文があれば差し替え候補に）
  - → **見直し案をユーザーに提示し、承認後に更新する。** 既存テンプレの記述（特にユーザーが手で直した箇所）は勝手に上書きしない。

### 4. 信頼度の明示

各種別テンプレの冒頭に **抽出元の見本リストと件数**を記録する。1〜2件依存の種別（現状: 事業計画＝1件、決裁説明＝1件）は「**要更新**：見本が増えたら見直す」と明記し、薄い部分を推測で埋め切らない。

### 5. 出力後

- MD の構造を壊していないか確認。
- **新しい種別・ファイル・参照を増やした場合**は、`impact-check`（EVENT: スキル変更）を実行し、`data-structure.md`・関連スキル（drafting / self-review / プロンプト生成スキル）への波及を確認する。

## 注意

- **デザインは抽出しない**（前述の線引き）。
- 見本が少ない種別は正直に「要更新」と記す（推測で埋めない）。
- 抽出・見直しはユーザーとの往復（承認）を伴うため、**メインで実行する**（サブエージェントに切り出さない）。巨大すぎてコンテキストに載らない場合のみ一次要約を Agent ツールに外注（`sonnet`）。
- 関係者名は **カタカナ**で確認してから記録（`data-handling.md`）。見本の作成者名（例: 切畑）も同様。
