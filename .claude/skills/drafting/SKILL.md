# 執筆（ドラフト作成）スキル

業務文書のドラフトを作成する「執筆モード」。**メインの会話の中で実行する**（下書き→ユーザーが修正→直す、という往復を前提とするため、別コンテキストには切り出さない）。

## ドラフト作成前に必ず参照する情報

1. タスクの背景情報（tasks.json の `context`）— なぜこのタスクが発生したか
2. PJのナレッジ（knowledge.md）— 経緯、決定事項、行間の補足
3. 関係者の情報（people.md）— 宛先の好み（結論ファースト等）、立場関係
4. レビュアーのFB傾向 — `.ai-secretary/global/review/people/<宛先>.md`（あれば）。過去の指摘パターン
5. テンプレート（`.ai-secretary/templates/`）— 該当するフォーマットがあれば使用

## ドラフトの種類と方針

### メール
- 宛先の人物の好み・立場を踏まえたトーンで書く
- 結論ファースト好みの人には冒頭に要旨を置く
- 社内メールは簡潔に。社外メールは丁寧に。ただし関係性が近い相手には過度にフォーマルにしない（people.md のトーン傾向を尊重）

### 報告書・提案書
- 報告先の好みに合わせた構成にする
- 段階に応じた完成度:
  - **骨子段階**: 構成案と各セクションの要点のみ
  - **ドラフト段階**: 本文を肉付け
  - **レビュー反映**: FB内容を踏まえた修正案
- 過去のレビューFB傾向があれば事前に反映（「GMは数字の根拠を重視」等）

### 議事録
- 発言の羅列ではなく、決定事項・アクションアイテム・議論のポイントに整理
- 参加者、日時、議題を冒頭に記載

### 週報
- **weekly-report スキルの手順に従う**（このスキルでは扱わない）

## セルフレビュー

ドラフト完成後、提出先のレビュアーが明確な場合は **self-review スキル**でセルフチェックを行い、修正提案をユーザーに提示する。

## 出力ルール

- **凝縮・フラット優先**（学習済みの好み / ins-20260529-001）: 冗長より凝縮。重要点に絞り、深い入れ子や副次トピックの列挙（来週予定・周辺進捗など）は省く。週報・報告書・MS/CDP共通。
- ドラフトを生成したら必ずユーザーに確認を求める（「このまま使いますか？修正しますか？」）
- ユーザーの修正内容は、今後の文体・トーン調整の参考として learning スキル（セクション7）で `observations` に記録する（source: `drafting`）
- 文章主体の成果物はチャット上に直接出力する（ファイル生成は必要時のみ）
