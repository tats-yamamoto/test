# セルフレビュースキル

## 前提: 必ず参照するデータ

1. 該当PJの `people.md` — レビュアーのFB傾向（定性情報）
2. `global/people.md` — レビュアーの全般的な傾向
3. `.ai-secretary/global/patterns.json` の `review_tendencies` — レビュアーの指摘パターン（定量情報）
4. 対象タスクの `review_history` — このタスクの過去のFB（差し戻し履歴がある場合）

## セルフレビューの手順

### 1. レビュアーを特定する

- タスクの次のレビュー段階のレビュアーを確認
- 多段レビューの場合、現段階のレビュアーに集中する

### 2. レビュアーの傾向を収集する

people.md と patterns.json から以下を確認:
- **よくある指摘ポイント**（構成、結論ファースト、数字の根拠、具体性 等）
- **好む文体・トーン**（簡潔さ重視、丁寧さ重視 等）
- **重視する観点**（実現可能性、コスト、リスク 等）

### 3. ドラフトをチェックする

レビュアーの傾向に照らして以下を確認:

- [ ] レビュアーが重視するポイントが明確に記載されているか
- [ ] 過去に指摘された同種の問題が再発していないか
- [ ] 結論・要旨が適切な位置にあるか（結論ファースト重視の人向け）
- [ ] 数字・根拠が具体的か（数字重視の人向け）
- [ ] 文量・粒度がレビュアーの好みに合っているか

### 4. 修正提案を出力する

```
## セルフレビュー結果

レビュアー: ○○さん
傾向: 結論ファースト重視、数字の根拠を必ず確認（過去N回中M回指摘）

### 修正提案
1. 【構成】冒頭に結論を移動することを推奨（○○さんは過去3回結論の位置を指摘）
2. 【根拠】P.3の「効果が見込まれる」→ 具体的な数値を追加（○○さんは定量的な根拠を重視）
3. 【問題なし】文量・トーンは適切

修正しますか？
```

## 注意事項

- レビュアーの傾向データがない場合は、一般的なレビュー観点でチェックする
- セルフレビューの結果はあくまで提案。最終判断はユーザーに委ねる
- レビュー後に実際にFBを受けたら、learning スキルで傾向を更新する
